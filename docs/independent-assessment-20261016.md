## 1. P0：上传省略版本时覆盖已有文件，与公开说明冲突

**已验证事实。** 10月16日，对专用合成目标先上传40字节，再上传不同的48字节；两次均未提供 expected_version。后者完成且回读确认替换。未对用户文件复现。
- 首次上传 operation：d133d355-3158-4a20-b072-a6be5f1026c4。
- 覆盖 operation：54a34c60-17fc-47df-96aa-076c8be93e57。
- 覆盖回读 operation：8c4898c8-bcb3-4669-bc53-c7754782417d。
- 原 SHA：0f0a686a3e7b0d84bd0a3e49437f162af2735d0ee4fdec1ef1b3cbb167082998。
- 新 SHA：99a54fb456f5cd139ac565264470a0158d10fa35e0d342bca9d3df1768c9a3c6。
- 同字节再次上传也成功，但不能把它算作不覆盖拒绝测试。

**根因与契约。** b036fc7（10月14日）将 transfers.rs 的 Staged.expected 改为 Option，移除省略时默认 absent；new/publish 仅在 Some 时检查版本，已有目标随后经 rename 替换。c10b483（10月15日）将相关测试改成省略版本时允许已有目标。tools.rs 的 file_upload 描述仍承诺 Default refuses overwrite。模型请求省略版本；连接器 schema 无 overwrite 字段或版本默认值；Gateway 源码克隆参数并处理文件 URL，未见自动补版本。托管连接器内部不可见，不能宣称已完整审计它。

**影响。** 工具调用者依照说明省略版本也可能替换内容；原子写只能避免半文件，不能防止意外覆盖。

**建议（用户已同意，未实施）。** 省略版本按 create-only 处理；显式 absent 同样只创建；显式当前 SHA 才允许替换。保留传输前及发布前双重版本检查、原子发布、幂等身份与恢复记录。

**兼容注意。** 依赖无条件覆盖的调用方需先读取当前 SHA；不能将旧的暂停操作静默改参数或自动重放。catalog、adapter、说明、固定验收脚本应同步。文本编辑另议。

**验收标准。** 新目标成功；已有目标省略/absent 拒绝且字节不变；正确 SHA 替换成功；过期 SHA、传输期间并发改动拒绝；重复原操作不重复写；取消/恢复不绕过原前置条件。

**状态。** 实测失败、现场保留；未修改上传实现或部署。现场证据在本机 target/dev-verify/generic-smoke-20261016/result.json，非公共发布附件。

## 2. P1：code_apply_edits 可选 CAS 与部分说明不一致

**事实。** 在现有 main 中，tools.rs 明示省略 expected_version 可不做 CAS；files.rs 仅在 Some 时校验。edit 的完整内容可写现有目标，delete 也未强制 CAS；create 仍拒绝已有目标。托管连接器说明及 docs/chatgpt-code-gateway.md 仍要求当前 SHA。源码历史涉及 b036fc7/c10b483。

**影响。** 不同入口说明使调用者误判并发修改保护；不应将 CAS 与账号/OS权限混为一谈。

**建议。** 开发者单独决定是否强制 CAS，或明确提供可选但有风险的模式；统一全部入口说明。用户只确认了上传方案，未确认文本编辑协议反改。

**兼容注意。** 不扩大当前修复范围，不取消原子写、精确替换、create保护、change_resume 对第三版本的冲突保护。

**验收标准。** 各入口对 create/edit/delete 的省略、absent、正确/过期 SHA 行为一致且有明确契约；多文件预检失败不误改其他文件；恢复保留并发用户内容。

**状态。** 源码确认，未对用户文件实测、未改设计。

## 6. P2：HO5升级fake-IP与跨项目PrivateTmp环境分开处理

**事实。** 原传输a3c6847f-b2c0-4602-bc6a-5fa323308122暂停：0确认字节、HTTP未开始、目标未改变。原下载域名为sdmntprwestus.oaiusercontent.com。10月16日前现场观察到系统解析经tun0返回198.18.0.16与fc00::10；resolvectl query明确标明tun0缓存来源。tun0承担全域DNS，目标路由亦经tun0。存在sing-box进程，但其exe/fdinfo元数据被OS权限拒绝，不能断言该进程生成假IP。证据operations：193816dd-3498-49b0-881d-14e6ca8e94a6、b602a5f0-a816-4c59-821a-ef9b0a5aa88f。

**原因。** transfers.rs 在HTTP客户端建立前拒绝任一非公网解析地址，是来源地址校验触发，不是目标文件权限或已观察到的HTTP授权拒绝；文件授权后来也过期，两种条件需分别解决。

**建议/验收。** 网络管理方查清原解析来源并恢复合法公网解析；验证连接及当前文件授权后，只恢复原传输。不得关闭校验、擅改DNS/代理或换通道绕拒绝。

**PrivateTmp边界。** 若跨项目临时路径因不同服务命名空间不可见，应通过该项目原执行器与相应服务状态单独取证；本批未新取证确认该现场条件。本报告没有足够证据证明HO5 fake-IP由PrivateTmp导致，也没有证据把所有跨项目断连归为RH缺陷。不读取原始环境/配置或擅自关闭PrivateTmp。

**状态。** 网络与独立执行环境依赖；不以相关性推因果，未改变网络/OS保护。
