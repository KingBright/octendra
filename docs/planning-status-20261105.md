# 规划与实际交付对账（2026-11-05，11-06 更新）

依据本仓库实现、O1–O8 / W1–W6 任务、隔离工作区实测记录和 Weavelo 的设备验收记录对账。这里区分“有基础代码”“独立实测”“部署验收”，不把跨编译、接口可调用或方案文档记作功能完成。

## 本次已交付：手机自己连接无线 ADB

0.12.7 只能通过外部已授权 ADB 激活 shell。0.12.8 新增应用内配对通知、AndroidKeyStore 身份、本机 mDNS 发现、本机 TLS ADB 和 helper 自动激活。远程通道仍使用原 Octendra 服务，配对码只从手机界面进入，不进入 MCP 参数。

已用原机主证书签名并安装到努比亚 NX741J（Android 16）和 Redmi 2409BRN2CC（Android 15）。两台均通过本机配对、UID 2000 shell、关闭 USB 调试后的 helper 自动恢复及远程文件读写，原生 MCP 上传、按版本覆盖和下载哈希也全部通过。源码为 `7a3a6bf`，34 项 JVM 测试和 29 项 Python 测试通过，lint 无错误。完整范围见[无线 ADB 真机验收](android-wireless-adb-acceptance-20261106.md)。

Wi-Fi 重连后远程通道恢复；两台系统均出现关闭无线调试或要求网络重新授权的情况，已由 Agent 远程处理系统设置和正常授权页面，再次连接成功。不能据此承诺绕过系统授权或已通过整机重启、首次解锁后的恢复。

## Weavelo：独立对话负责推进

以 `remote_play/docs/testing/2026-11-05-DEVICE-ACCEPTANCE.md` 为证据。管理主界面、单流远控窗口、统一操作入口和菜单快捷操作已进入实机交付，不应继续笼统列为“尚未开发”。129 桌面版和 81 Android 版的设备图标、窗口来源等验收由该对话继续；不要在它操作手机时重启相关会话。

仍未闭环的是 AI 隔离来源和共享输入接管的 W1–W3 联合验收、Windows/Linux 原生 GPU Computer Use 导出与语义树、全设备音频/相机/通知/多窗口/旋转/输入法的长时矩阵。已记录的具体问题包括 HO5 锁屏无法验收实际输入、Linux 全分辨率首帧编码超目标、努比亚微信输入法异常，以及 Redmi 的系统自动化输入限制。部分文件传输、应用流和音频实测已通过，不能据此声称整套跨平台 phone use 已完成。

## 后续落地顺序

1. 将已验证的 Mac 隔离来宾接入现有正式登记和服务生命周期，做到 Agent 默认可用；同步修复 Android 工作区自动寻址和基础文件操作。
2. 在真实手机补齐 O2/O3 的显示、输入法和任务生命周期，验证前台正常使用时后台不干扰。
3. 按实际设备条件交付 Windows/Linux 持久隔离工作区，并逐平台实测。
4. 在以上真实上下文中补齐语义选择、局部查询和效果验证，再按用户安排开展两项目联合测试。

每步沿用 main、原构建/签名/安装入口；不增加发布分支、额外审批或第二套任务授权。
