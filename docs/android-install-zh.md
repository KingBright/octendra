# Octendra Android 0.12.8

这是安卓**被控设备端**：手机在完成接入和授权后，可由 Octendra 网关及其已授权调用方操作。它不是用来控制电脑的 Weavelo 客户端。

## 安装和配置

安装当前由原机主密钥签名的 APK，打开 Octendra。构建机上的交付文件为 `android/app/build/outputs/apk/release/app-release.apk`，版本以 `android/version.properties` 为准。安装包没有内置服务器地址、设备令牌、登录密码或用户数据。

在服务端为手机注册一个独立设备，得到配置。不要复用电脑的设备 ID 或令牌。应用支持手动填写，也支持导入 JSON。必填字段：

```json
{
  "gateway_url": "https://你的网关域名",
  "device_id": "服务端为这台手机生成的 UUID",
  "device_token": "服务端为这台手机生成的独立令牌",
  "name": "我的安卓手机"
}
```

`gateway_url` 填 HTTPS 源地址，不加 `/mcp` 或其他路径。配置示例中的说明文字需要替换为真实值。令牌是凭据，不要公开分享或截图发送。

保存配置，阅读提示并开启远程连接。系统设置中开启本应用的无障碍服务，按需授予通知和安装未知应用权限。连接状态、无障碍状态和 shell 连接状态是不同的能力，必须分别确认。

当前网关的设备注册由其已有的 `enroll` 管理命令完成；使用配置文件启动的网关会自动加载有效的设备注册变更。APK 不会自行注册为管理员，也不会尝试绕过服务器认证。仓库 `docs/android-agent.md` 包含注册及构建命令。

## 普通授权后能做什么

支持读取可访问的页面结构、按控件点击或长按、中文等 Unicode 文字输入、滑动、返回、主页、最近任务、通知栏、截图、应用列表和启动应用。

文件传输使用应用专用的共享工作区。远程工作区不会暴露保存连接凭据的私有目录。当前每次文件传输上限为 64 MiB。

普通安装方式会在手机显示安装确认通知，仍需用户确认；系统未完成安装时不会报告为安装成功。

## ADB / shell 增强能力

应用已包含辅助进程，不要求另外安装 Shizuku。开启应用内 shell 开关后，优先使用下文的手机内无线激活；也可以沿用已授权电脑上的脚本：

```sh
python3 scripts/android-activate-shell.py --serial <ADB设备序列号>
```

默认从电脑的 PATH 查找 `adb`，也可通过 `--adb <Android SDK 中的 adb 路径>` 指定。电脑与手机需要事先完成 USB 调试授权或无线 ADB 配对。

激活后可执行 shell 命令、读取 shell 有权限访问的文件，以及通过系统包管理接口安装应用。该身份通常为 Android `shell`（UID 2000），并不是 Root。

从 0.12.8 起，可在手机内完成无线 ADB 配对。开启远程控制后点“无线激活 shell（无需电脑）”，在系统无线调试页面选择“使用配对码配对设备”，保持该页面打开。已允许读屏时，应用会在手机本地读取该系统页面的配对码并完成配对，无需复制或发送给 Agent；未启用读屏时，可从 Octendra 通知输入六位配对码。应用只连接本机，配对身份保存在 AndroidKeyStore，配对码仅在内存中用于本次配对。

配对后，应用在现有远程控制和 shell 开关开启时发现本机无线调试服务并自动激活辅助进程。切换网络或辅助进程退出后会重新发现和连接。手机重启后的恢复还取决于系统无线调试和 Wi-Fi 是否可用，厂商关闭无线调试时会显示“等待系统无线调试可用”。系统中忘记 Octendra 配对后需重新配对。停止远程控制或关闭 shell 开关会停止自动激活。

两部真机已通过关闭 USB 调试后的辅助进程自动恢复和远程文件读写。Wi-Fi 重连或切换接入点时，系统可能关闭无线调试或再次要求网络授权；现有远程通道可恢复，Agent 可通过已有 shell / 无障碍能力处理系统设置和授权页面，之后应用重新发现连接端口。系统撤销授权、整机重启和首次解锁后的完全无人值守恢复尚未完成实测，不能等同于普通断线重连。详见[本次真机验收](android-wireless-adb-acceptance-20261106.md)。

远程 Agent 使用 `android status` 查看 `wireless_adb`，使用 `android adb_pairing` 开始本地配对，或使用 `android adb_reconnect` 重连已配对的本机 ADB。配对码在手机本地处理，避免进入命令日志。

## 在聊天中使用

手机注册、连接并完成所需授权后，可让已连接 Octendra 的助手先检查设备列表，再读取该手机的能力。上层复用现有 `workspace_open`、`terminal_exec`、`file_upload`、`file_download` 和操作回执工具，安卓动作由 `android ...` 命令分发，因此不依赖新增聊天工具入口。

例如可以提出“查看这台手机当前页面”“打开某应用并检查页面”“安装我提供的 APK，然后确认包名和版本”。涉及发送、删除、付款等实际副作用的操作仍须遵守用户的具体授权。

## 停止和边界

应用内和前台通知均提供停止远程控制入口。关闭 shell 开关会断开辅助进程，系统无障碍权限也可随时撤销。

安全窗口可能拒绝截图，部分应用不提供完整的无障碍节点。应用不会声称拥有所有系统权限，不绕过安全窗口或应用沙箱。后台存活、锁屏、重启和厂商省电策略还需要在实际手机上验证。

断线后只重送已保存的操作结果，不自动重复有副作用的命令。执行中进程丢失时结果标记为未知，必须先检查当前状态。

测试专用页面、测试工具和本地测试证书只存在于单独的调试/测试构建中，不属于用户安装的 Release APK。签名私钥由构建机单独保管，不在仓库或安装包中。
