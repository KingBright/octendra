# Weavelo 平台操作任务

本任务单落实[平台操作技术方案](../ui-platform-implementation-plan.md)，供 Weavelo 当前设备任务结束后执行。本次仅把任务记录在 Octendra 仓库，未修改 remote_play，也未向正在运行的对话派发新的实现工作。

目标是在既有媒体和远程控制产品中展示并操作 Octendra 拥有的后台界面。保持现有原生渲染、编码、设备组、文件传输、签名、视觉语言和现有功能，按[主界面与单流远控窗口规划](../weavelo-window-ui-plan.md)重组界面职责。平台机制源码对照基线 03f0f20，后续 UI 规划对照 051b4fe；实施前读当前 main 和最新 AGENTS.md，保留当前任务的变更。

## W1 统一来源描述和协议映射

优先级 P0，与 O1 定义同一份上下文；共享协议文件同一时刻一个写入任务。

- 将具体 device、view、generation、source_revision、资源版本和 app_instance 映射到现有来源目录。区分 MainDisplay、普通窗口、相机和 Android AI 显示。
- 保留实际应用名、窗口名、实例名称、图标、尺寸和旋转。Android 来源不能继续把所有输入写死为 MainDisplay。
- 明确来源可观看、可语义操作、可原始输入、是否后台及实际焦点影响，分别表达设备离线、来源恢复和系统授权缺失。
- O1 提交约定后在本项目实现映射，验证与 Octendra 的样例数据一致；不另建第二套用户任务授权或独立网络身份。

主要入口：现有 protocol 来源与输入结构、host/source_catalog、remote_core、Android PublisherClient.kt 及 UI 来源列表。已有 source revision、应用图标和 committed UTF-8 文本协议继续复用。

独立验证：协议与目录夹具中主屏、AI 屏和相机不会串源；旧 generation 的输入不能作用到新的原生 display；同一应用的不同实例可以辨认。

## W2 Android AI 屏媒体接入

优先级 P0，依赖 O2 的显示生命周期和双方确认的 Surface 接口。

- 通过受验证的本机 Binder 接入 Octendra 的 view，按真实调用 UID、包和现有签名身份绑定。不能假设两个 App 同签名，也不新增可被局域网直接访问的 helper 端口。
- Weavelo 管理 MediaCodec 编码器及其 Surface；Octendra 管理显示及 GPU 帧入口。一个入口把原生帧渲染到编码器，AI 明确请求时才读回图像。
- 复用 SurfaceHevcEncoder、既有媒体需求和原生传输；保留 HEVC、色彩元数据、编码器尺寸对齐和关键帧机制。
- 消费者解绑不销毁 AI 显示或应用；Binder 消亡、编码器重建和来源变化分别释放自己的资源。当前主屏 MediaProjection 和相机路径保持各自的真实 OS 授权与来源。
- 初期验证可先使用测试源 Surface；Bitmap 每帧复制、低分辨率预览和 MCP 图片轮询不能作为完成的实时视频路径。

主要入口：android/.../ProjectionService.kt、SurfaceHevcEncoder.kt、PublisherClient.kt，以及既有媒体桥接。新增组件只承担受验证 Surface 绑定和所需的 GPU 渲染，不建立新的媒体协议栈。

独立验证：测试帧确实被编码、传输、解码并显示；观看端进出不终止生产任务；尺寸变化和反复绑定无悬挂 Surface 或持续内存增长。记录各阶段时间，不能把 encoder 接收帧当作屏上呈现。

## W3 共享执行和人工接管

优先级 P0，依赖 O1/O3 的资源身份和任务归属。

- AI 屏输入进入 Octendra 的同一个执行后端；不发送到默认显示，也不与另一个无障碍注入器竞争。
- 触点与画面使用同一内容矩形和逆变换，覆盖缩放、裁剪、键盘 inset、旋转及显示重建。来源或几何变化取消旧手势。
- 人工交互携带明确来源和既有事件身份，接管冲突资源时使资源版本变化，取消待发 AI 输入，释放 AI 持有的键和触点；其他来源保持运行。
- committed UTF-8 文本按既有协议传递，不退回逐字模拟键盘；目标显示和编辑器由执行端验证。长文本分段保持原事件去重和 Unicode 边界。
- 人工归还后由 AI 新观察再继续；没有额外逐动作申请控制权的弹窗。不能依靠一段固定空闲时间就断言所有本地用户操作已经结束。

主要入口：现有 realtime_input、workspace_input、publisher_input、平台 InputInjector / Android 输入桥，以及来源的交互焦点和取消路径。

独立验证：相同画面点击位置正确；切换来源或旋转的旧事件不落地；人工接管后旧 AI 输入不执行；中途断线无悬挂键；主屏用户组词时后台文本不进入该编辑器。

## W4 管理主界面和单流远控窗口

优先级 P1。管理主界面、单流窗口和菜单栏可先基于现有会话独立实现；AI 新来源接入时对齐 W1，真实 AI 屏展示与共享输入依赖 W2/W3，不阻塞当前来源的 UI 交付。

- 按[窗口规划](../weavelo-window-ui-plan.md)的 U1 到 U6 实施：设备、活动、传输和设置集中到管理主界面，每个远控窗口固定绑定一路推流或拉流，可并行打开多窗口。
- 每个远控窗口使用同一套操作栏，携带明确设备和流上下文；文件默认绑定当前设备，新拉画面默认另开窗口，明确替换才改当前来源。主界面和菜单栏复用同一操作处理路径。
- 扩展 macOS 系统菜单栏及 Windows / Linux 托盘，提供活动窗口、常用设备、文件和停止发送等快捷入口。无管理窗口时仍读取同一后台所有者状态。
- 显示真实设备、应用、来源和输入归属，区分等待首帧、休眠、离线、恢复和系统授权问题。手机主屏、AI 显示和相机使用同一来源目录；交回后保留页面和应用任务。
- 管理窗口关闭不停止其他任务，推流预览关闭不停止发送；拉流按展示引用管理寿命。PiP、文件、音频、剪贴板、文字及物理键、画质、暂停、遥测与原生呈现逐项保留。
- 可选 Agent 光标只用于表示目标，不移动真实鼠标，也不宣称产生第二套 OS 光标。Android 使用管理页与单流远控页，保留直触和触控板，按真实平台能力提供多窗。

独立验证：按窗口规划的功能去向表逐项核对；多设备、多来源和菜单栏操作不串目标；关闭窗口、传输和流的生命周期符合定义；实际截图、呈现、全屏、DPI、错误及恢复分别验收。

## W5 媒体恢复和平台性能

优先级 P1，随 W2/W3 持续验证。

- 切网、编码器重启、接收端重连与 Octendra helper 重建按具体来源恢复，新的 generation / revision 不复用旧画面输入。
- 保留原生 GPU 呈现、真实颜色和 SPS / 格式信息。不能猜测 YUV 矩阵以掩盖来源信息缺失，也不能丢压缩参考帧来代替合理背压。
- 分别测量发送首帧、接收解码、实际呈现与动作反馈，观察 CPU、内存和网络需求变化。使用同任务、同设备、同画面设置的既有基线比较。
- 应用级后台控制在 macOS、Windows、Linux 由对应语义适配器与真实来源能力决定；多个窗口视频成功不能替代后台输入验收。

独立验证：长时间运行、观看者来去、网络改变、显示息屏计时和旋转后仍能操作；受保护或不可渲染内容返回真实原因；其他在途来源不受影响。

## W6 交付和独立汇报

在 remote_play 唯一主 main 工作目录使用现有构建、测试、打包和安装入口；每个小迭代相关检查后显式提交、推送并核验远端。不创建功能分支、额外 worktree 或新的发布门禁。

复用 scripts/test_release.sh、既有 macOS 正式签名打包与安装、Windows、Linux 和 Android 的正式构建入口。保持签名证书、包名、数据、设备组、媒体和文件传输身份。遵守当前仓库对原生呈现、颜色、协议、当前产物和在途操作的要求。

依据 inventory 列出实际安装 Weavelo 的每个节点，核验包、安装及运行身份；没有安装的节点明确记不适用，离线节点记未完成。自己的测试先在专用来源和设备上进行，不改变另一对话仍在使用的服务。

汇报源码提交、相关测试、正式包、已升级设备、真实视频与输入效果、恢复和未完成项。与 Octendra 的联合测试由用户安排，不能在计划完成或单边测试通过后自动宣称整套升级完成。
