# Octendra / Weavelo 开发边界与独立任务

日期：2026-11-06。依据用户本轮要求，两个现有对话各自开发、验证、升级和汇报。本文件明确职责，沿用既有 O1–O8 / W1–W6 编号，不另建一套项目或发布流程；与旧任务描述冲突时，以这里的归属为准。

**Octendra 负责让 Agent 找到正确执行环境并完成操作；Weavelo 负责让用户实时看见、控制和接管该环境。** 外部 Agent 决定业务任务和业务确认，两个工具均不新增逐动作审批、租约续期或人工版本门禁。

## 唯一责任方

| 能力 / 问题 | Octendra 对话（remote_hosts） | Weavelo 对话（remote_play） |
| --- | --- | --- |
| 对 AI 的通用 computer / phone use | 维护 `ui_observe` / `ui_act`、上下文选择、语义查询、效果验证、操作记录和去重 | 复用执行能力；现有码流观察、原生媒体诊断工具保留，不重复建设业务 Agent 循环 |
| 持久强隔离环境 | 创建、登记、启动、恢复 VM / Android 可用实例，持有应用、显示及任务生命周期 | 展示工作区来源；在已登记来宾中通过既有管理通道安装自己的媒体组件，不再创建另一份 VM |
| Android 无线 ADB / shell | 配对、身份、发现、helper 激活及恢复；0.12.8 已完成两机验收 | 消费已可用的来源，不另建无线 ADB 或 shell 激活体系 |
| Android AI 后台屏、分身与输入法 | 显示保活、package + user、task 恢复、深链归属、目标编辑器及输入验证 | 将该屏作为明确来源展示；发送携带来源身份的用户输入，不创建或移动该屏中的应用任务 |
| 桌面 / 浏览器自动化 | 工作区内 AX / UIA / AT-SPI、网页 profile / page 持久上下文、语义动作和结果验证 | 现有手动宿主远控、窗口采集和原生媒体来源继续维护；AI 工作区输入交给同一 Octendra 执行端 |
| 实时音视频及连接 | 提供执行环境和真实可用画面入口，不承担视频编码、实时流或视频中继 | 采集适配、GPU 图像消费、编码、P2P / 中继、解码、呈现、音频 / 相机及媒体性能 |
| 远控产品界面与多开 | 提供真实设备、工作区、来源和能力状态 | 管理主界面、单流窗口、统一操作栏、设备快捷操作、菜单栏 / 托盘、触控和手势 |
| 人工接管 AI 来源 | 处理资源归属变化、取消待发 AI 输入、释放其键/触点、交回后重新观察 | 采集接管意图、显示实际状态、释放自身输入；关闭查看窗口只解绑媒体 |
| 文件 | MCP 文件读写、版本校验、Android 原生编辑/删除、断点续传和自动 workspace 寻址 | 文件面板、拖放、传输进度、现有 P2P 文件协议；发往 AI 工作区时绑定正确执行节点 |
| 剪贴板 / 音频 | 恢复 AI 动作真正修改过的应用状态，保留用户后续更改 | 用户选择的远控会话剪贴板同步、音频路由、音量和静音 UI；不接管 AI 的应用状态恢复记录 |
| 恢复 | Agent、helper、工作区、应用和操作结果；不因重连重放未知业务动作 | 媒体会话、编码器、解码器、Surface 和观看窗口；不因重连重建应用或工作区 |
| 节点交付 | Gateway、Octendra Agent / APK、MCP 与 Skill、实际运行身份；RPi 400 待联网后处理 | Weavelo 桌面 / APK / 后台组件、自己的发布渠道及节点验收 |

Android 的 IME 问题按发生点归属：Weavelo 自己输入框的组词、手势到事件的转换由 Weavelo 修；Octendra AI 显示中的焦点、InputConnection 和目标文字投递由 Octendra 修。普通宿主手动远控仍由 Weavelo 维护。不能仅凭“手机输入失败”把整个问题交给另一项目。

## 两项目只在这些接口上相接

以下是职责与信息含义，不是新增工具参数；实际字段沿用已有协议。尚未实现的扩展须随所属代码提交再使用，不能把草案当成可调用接口。

| 接口 | 提供方及消费者 | 约定 |
| --- | --- | --- |
| 执行来源描述 | Octendra 提供，Weavelo 映射到自己的来源目录 | 标明宿主、实际执行设备、工作区 / view、实例、代际、几何和能力。执行身份及资源修订由 Octendra 维护；Weavelo 的媒体会话修订不能代替执行代际。名称、图标和媒体展示由 Weavelo 映射。 |
| 原生画面绑定 | Octendra 持有显示 / GPU 帧入口；Weavelo 持有编码器及消费者 Surface | Android 使用已验证的本机 Binder 边界，不假设两 App 同签名，不新开网络 helper 端口。消费解绑只释放本消费者；显示重建通知新代际。桌面使用真实来宾来源。实时画面不经 MCP 截图轮询。 |
| 来源输入与接管 | Weavelo 发送事件；Octendra 执行 AI 来源上的动作 | 事件绑定同一来源、代际、几何和既有事件 ID。Weavelo 将视口位置转换到所显示内容坐标；Octendra 只做内容到原生目标的映射，避免重复旋转或缩放。Unicode 文本保持提交文本语义。代际变化取消旧事件，不投递到默认主屏。 |
| 状态及恢复 | 各自报告自己拥有的状态，Weavelo 合并展示 | 区分执行端离线、来源恢复、系统授权缺失、等待首帧和媒体断线。Octendra 不通过重装环境修视频；Weavelo 不通过重启 helper 修解码。来源变化后重新绑定，不沿用旧画面输入。 |

Octendra 在自己的协议和适配器提交中附真实来源样例与有界契约测试；Weavelo 在自己的仓库消费并测试映射。双方只修改自己的代码，接口变更附提交和兼容说明即可，不新增审批流程。媒体或 UI 可使用现有来源和测试 Surface 先行验证，不等待全部 Computer Use 完工。

## 本对话的 Octendra 队列

1. **O7 + O1 最小接入**：把已实测的 Mac 持久来宾接入正式登记、GUI 服务和 Gateway，交付真实工作区来源描述、独立观察及共享输入的最小契约。保持强隔离默认目标。
2. **Android 易用性与恢复**：修复默认 workspace 解析，补原生文件编辑 / 删除与 checked 等状态；继续 helper / 应用 / 显示恢复及重启、首次解锁验收。无线 ADB 已交付，不重复开发。
3. **O2 / O3**：两部真机补后台显示保活、主屏中文输入共存、已有 profile / 分身、task 停放和恢复。传输断点续传按既有协议补齐。
4. **O7 跨平台 + O4 / O5**：Windows / Linux 持久隔离工作区，以及各平台语义和浏览器连续使用。每个平台独立实测。
5. **O8 贯穿每次迭代**：本项目检查、main 提交推送、自己的组件升级及真实运行验收；离线节点明确保留未完成。

## Weavelo 对话的队列

1. **先完成当前 W4 / W5 在途工作**：现有 GUI 已交付；继续其正在进行的桌面 131 / Android 83 手势、画面调整、输入和平台媒体验证，不退回重做 GUI 方案，也不因本分工中断测试。
2. **W1 / W2**：来源目录映射、AI 工作区展示、测试 Surface 的原生编码到实际呈现；在 Octendra 已提供来源后接入真实画面。
3. **W3**：AI 来源上的共享执行输入、几何转换、人工接管 / 交回；与普通宿主手动远控明确区分。
4. **W5 / W6**：首帧、延迟、长时运行、网络切换、音频 / 相机 / 通知 / 旋转 / 多窗口矩阵，沿自己的正式发布和逐节点升级完成独立汇报。

这些顺序允许修复已经定位的小问题，不要求先完成所有上游任务再提交下游改进。各任务以实际最新源码和验收记录为准，版本号仅说明本次交接时正在进行的工作。

## 独立完成与交接

- Octendra 验收执行环境中的观察、点击、文本、文件、恢复和宿主不受干扰；Weavelo 验收真实采集、编码、传输、解码、呈现和输入结果。接口夹具通过与真实跨项目运行分别记录。
- 每个对话只在自己的唯一 main 主工作目录开发、提交、推送和部署；不修改、提交或清理对方仓库 WIP，不重启对方正在使用的服务。
- 共用手机或重启同一设备时只同步占用时段和完成状态。对方正在测试则继续本项目不依赖该设备的工作，不引入长期锁或审批队列。
- 发现跨边界问题时发送最小复现、来源 / 操作身份、预期与实际结果和已有证据；按上表定位责任方，自己先完成已确定属于自己的部分。
- 两边在各自对话向用户汇报。用户决定联合验收时机；单边完成、来源上线或虚拟机启动均不等同于整套体验通过。
