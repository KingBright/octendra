# Octendra 平台操作任务

本任务单落实[平台操作技术方案](../ui-platform-implementation-plan.md)。目标是在既有 ui_observe / ui_act 下完成应用级后台操作、独立观察和恢复，复用当前连接授权，保持外部 Agent 的业务循环。

源码基线 8a3e4e5。现有两个工具、模拟器后台屏和去重实现继续使用；下面的工作尚未因方案提交而完成。只在 remote_hosts 主 main 和现有主工作目录开发，每次小迭代完成相关检查后提交、推送并核验远端。

## O1 统一上下文和并发状态

优先级 P0。第一项实施；共享字段与 W1 对齐后提交一次作为双方适配依据。

- 在现有协议和工具 schema 中增加可选 target、局部 query 和 expect，保持两个入口和原有默认参数可用。更新 adapter-contract 和 Skill 文档；不暴露 PID、session、task lease 或手动续期。
- 具体上下文包含设备、应用实例、view、generation、source_revision 和资源版本。Android 应用实例使用 package 与 user，浏览器实例包含 profile / page，桌面绑定进程实例而非可复用的裸 PID。
- 将 ui_access 的设备级串行范围拆成资源调度；Android perform 不再把不同来源的只读操作全部阻塞。真实共享物理输入仍有统一顺序。
- 按 observation_id 保存有界的不可变观察，不能由同账号下另一对话的 observe 覆盖。活跃操作和必要的原生对象身份受保护；缓存淘汰返回可继续的新观察，不结束业务任务。
- 修改前检查资源版本并保留现有持久化 operation_id。明确未发送、已发送未验证、验证成功和结果未知，保持未知动作不重放。
- 读取、光标闪烁和无关动画不让其他任务的观察失效；expect 按原目标的真实身份重新定位，不能沿用新树中碰巧相同的元素序号。

主要入口：crates/octendra-code/src/ui.rs、ui/image.rs、tools.rs、gateway.rs、agent.rs、job_dispatch.rs；crates/octendra-desktop-protocol/src/ui.rs；Android UiController.kt、UiContract.kt、AccessService.kt。

独立验证：同 owner 的两个对话保存不同观察并分别使用；不同应用读写能推进；同资源写入有序；原生 ID 重用和 helper 重启不会接受旧 ref；重复请求仍指向原操作。测试断言实际目标及输入结果，不只检查锁的实现。

## O2 Android 显示和输入隔离

优先级 P0。保活和已有输入检查可在当前接口先修；新媒体绑定及完整能力描述与 O1 的上下文对齐，不等待全部调度重构才开始。

- 检查真实 trusted、own focus、no top-focus stealing、display group、尺寸和旋转，按系统构建和 helper 身份维护能力结果。没有独立能力时不得自动用影响主屏的模式代替。
- 实现显示组级保活与释放；验证超过设备息屏计时后仍有新帧、按键和目标控件变化。区分空显示、休眠、受保护黑帧与来源死亡。
- 每次输入绑定显示、目标应用及窗口或 UID；记录并释放本操作持有的键和触点。按动作标记是否会影响整机，不把 Home、最近任务、电源、音量一概声明为局部操作。
- 语义文本优先；InputConnection 必须匹配目标上下文。处理 WebView、选区、插入与替换，验证输入后的目标值。
- 必须使用粘贴时实现保存与条件恢复，用户新复制的内容优先，密码不经剪贴板。不能把主屏 IME 的组词结果提交到后台，或反过来。

主要入口：BackgroundView.kt、ShellUiService.kt、IUiShell.aidl、AccessService.kt、UiController.kt。Mika DisplayAwake、ScreenAccessibility、AndroidScreen 和 FrameMath 为机制参考，选取代码需保留来源。

独立验证：模拟器覆盖创建、销毁、休眠计时与输入取消；两部真实手机分别验证主屏中文输入与后台操作并行、软键盘变化和屏幕熄灭。没有独立输入法能力时记录具体动作缺口，不声称通过。

## O3 应用实例与任务生命周期

优先级 P0，依赖 O1/O2。

- 识别系统已有且可用的分身、工作资料和其中安装的应用，返回自然名称。启动检查、实例占用和启动后核验使用同一资源事务；不创建新资料，不复制登录数据。
- 跟踪本显示拥有的任务及原生实例，优先恢复原 task。任务 ID 重用、系统认证器和用户接管的任务不能自动移走。
- 记录动作引起的主屏任务到达与用户交互元数据，处理明确可归因的深链外溢；保持原调用上下文，不通过重新发起链接代替移动既有任务。
- 正常完成时安全停放应用并保留页面。移动机制不支持时保留可见的恢复状态和拥有的后台来源；不静默释放并销毁工作。
- 对真正修改过的音频状态建立按应用实例的恢复记录。尊重用户后续修改、现有前台使用及任务对播放内容的要求。

主要入口：ShellUiService.kt、BackgroundView.kt、UiController.kt；新增类只对应已证明需要的实例、任务和局部状态管理。参考 Mika AppCopies、MainScreenSpill、AppsAfterTask、AudioMuteLedger 和 ShellClipboard。

独立验证：已有分身使用正确 user；无分身明确不适用；后台跳转不会抢走前台应用；系统选择器、认证器与用户点击后的页面分类正确；完成后页面可再次接续；helper 被杀后没有遗留静音或覆盖用户剪贴板。

## O4 桌面语义和应用选择

优先级 P1，可在 O1 后独立推进。

- 增加应用与窗口解析，观察返回真实语义元素和可用动作。先补 macOS AX，再补 Windows UIA 的 Value、Selection、Toggle 等，Linux 接 AT-SPI；原有窗口图像和事件路径继续按实际能力使用。
- agent-desktop 作为候选原生后端做有界适配，先验证目标应用再扩大覆盖；保持原生对象身份和 ABI / 线程约束，不删除其同用户写锁来制造虚假的并发。
- type_text、fill、set_checked、select_option、expand 等使用各自语义。多显示、缩放、窗口遮挡与窗口关闭不改变动作目标。
- 每个动作返回实际投递机制、焦点和光标影响及结果证据。后台事件投递与完全独立输入空间分开报告。
- 签名兼容升级自动续接既有已授权执行记录，避免二进制哈希变化再次触发任务批准；保留真实 OS 授权和目标身份检查。

主要入口：computer_use/macos_worker.rs 及 window 模块、windows_native.rs、平台 worker、ui.rs、desktop protocol。使用现有工具链、Cargo target 和签名路径；导入源码或 FFI 组件的许可证随产品保留。

独立验证：每个平台用自有测试应用验证后台语义操作与前台另一个应用同时使用；验证两个同名窗口、列表重排和移除元素；Windows 管理员窗口、Linux 缺少图形会话等情况报告真实边界。跨编译不记为目标平台运行通过。

## O5 持久网页上下文和效果反馈

优先级 P1，依赖 O1；可与 O2/O4 分开实现。

- 复用已有可控浏览器；托管浏览器维护持久 profile。当前用户正在使用的 profile 不能被第二进程同时打开，不复制其他浏览器的私有 Cookie 数据库。
- 已有网页接口能满足时直接复用；只有实测的渲染或会话缺口才引入 Android 自有 WebView 宿主，不额外建设一套用户必须配置的浏览器产品。
- 页面 view 绑定浏览器实例和 page target，网页语义操作与原生对话框保持来源关联。Android 自有 WebView 宿主独立于第三方 App 的 shell 显示适配。
- 保留页面借出、人工接管和交回的身份与进度。Cookie、页面内存状态、应用登录各自说明恢复边界。
- 实现紧凑语义树、缓存查询、局部展开和后续变化结果；OCR 只标为像素证据。expect 校验目标状态，等待事件和局部画面，不使用整屏动画来判定动作一直未完成。
- 登录失效、验证码和服务退避返回具体状态并保留续接位置。桌面视口适配不默认启用浏览器特征伪装。

独立验证：普通浏览器重启后已授权登录连续；页面接管前后状态一致；网页编辑触发应用实际逻辑；假成功、延迟反应和未知提交都不会导致重复业务动作。只使用授权测试账户和自有测试页面测量。

## O6 已授权运行状态恢复

优先级 P1，与相关平台实现持续同步。

- 复用既有网络监测和请求日志，区分设备连接、helper、无障碍绑定、显示和媒体消费者状态。
- helper 重新绑定验证真实调用身份并更新 generation；恢复显示和应用上下文后重新观察。
- 按既有本地启用意愿修复系统回收的服务；用户停止、禁用或尚未授予的 OS 权限不被覆盖。保留其他服务与现有注册。
- 记录本任务的局部状态恢复，处理 App 与 helper 不同死亡顺序；观察原在途操作，不把网络恢复变成动作重放。

独立验证：断网、切网、USB 拔插、进程死亡、开机和首次解锁分别有结果；人为停止后不复活；旧观察不能向重建来源输入。

## O7 平台隔离扩展

优先级 P2，仅针对原生后台语义不能完成的具体任务。

- Linux：验证一个任务拥有的嵌套 compositor 能运行新 App，并拥有单独显示与输入；与用户现有会话、DBus、profile 和文件授权分清边界。
- macOS / Windows：先验证已有来宾或独立会话的实际抓图与输入；Windows 新建 Desktop 和 macOS 增加显示器不作为成功条件。不得修改系统安全或会话许可限制。
- 复用既有节点和执行上下文注册，来宾确实需要时才准备。没有需求时不在全设备安装 VM，也不为所有动作增加选择模式的流程。

输出为支持与不支持的具体场景、最小后端和实测证据；不能用架构图代替平台能力。

## O8 持续交付与逐节点对账

每个可交付迭代运行相关现有检查，显式提交、推送并核验主分支，复用 scripts/test.sh、正式 builder、fleet-upgrade、macOS one-shot updater 和原验收入口。Gateway 先于 Agent。Android 及 macOS 保留正式签名，不创建替代证书，不导出钥匙到其他机器。

对账当前 inventory：NAS、两台 Mac、cube、HO5、Reachy Mini、RPi 400 和两部 Android；只在实际装有客户端的设备同步 Codex / Antigravity MCP 和 Skill。网页连接检查实际工具目录及业务调用。未在线节点保留为未完成，不用其他设备替代它。

交付报告逐项列源码 SHA、远端、检查、签名包、实际安装与运行 SHA、真实 read/act、恢复和遗留问题。另一对话正在测试的设备必须先协调时机，不中断它的在途任务；各项目先独立汇报，联合测试按用户安排执行。
